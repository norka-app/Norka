# Заметки к выпускам

На каждый тег — один файл. Имя файла точно такое же, как у тега: для `v1.2.3` это `v1.2.3.md`. Текст пишем по-русски, в Markdown. Он попадает на страницу выпуска GitHub и в окно «Что нового» в Norka.

## Как выпустить версию

1. Добавьте файл заметок и влейте его в `main`.
2. На `main` поставьте тег и отправьте его:

```bash
git tag vX.Y.Z
git push origin vX.Y.Z
```

Сборка по тегу сама подставит текст из файла и допишет блок из `windows-smartscreen.md`. Если файла для этого тега нет, выпуск всё равно публикуется: в описании остаётся только этот блок.

Тег с дефисом становится предварительным выпуском. Пример: `v1.2.0-beta.1`. В WinGet такие версии не отправляются.

Если текст поправили уже после публикации, достаточно влить файл в `main`. Есть выпуск с таким тегом — описание обновится. Тега ещё нет — файл просто лежит в репозитории, и его подставит сборка, когда тег появится.

## Блок про Windows

В файлы `vX.Y.Z.md` не копируйте предупреждение SmartScreen. Сборка по тегу сама дописывает в конец описания `windows-smartscreen.md`: что нажать в окне, как сверить `SHA256SUMS` и как проверить аттестацию. Если в заметках уже есть маркер `<!-- norka:release-footer -->`, второй раз блок не добавляется. Окно «Что нового» обрезает описание с этого маркера, поэтому хвост остаётся на странице выпуска и не показывается в приложении.

Тот же хвост дописывает workflow «Release notes», когда правит уже опубликованный выпуск. Без этого правка заметок стёрла бы блок, потому что описание заменяется файлом целиком.
