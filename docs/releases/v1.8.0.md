## Русский

Конфиг можно импортировать, перетащив файл .toml в окно Norka. Выпуск 1.7.0 не публиковался: его тег указывал на старый коммит и был удалён. Здесь всё, что должно было войти в 1.7.0, и правки после него.

## Новое

- **Импорт перетаскиванием.** Перетащите `config.toml` в окно, и Norka запустит тот же импорт, что и кнопка «Импорт» в настройках, с подтверждением. Работает в простом и расширенном режимах. Пока файл над окном, видна панель с пунктирной рамкой. На файл другого типа или на несколько файлов сразу Norka отвечает подсказкой и ничего не меняет.

## Исправлено

- **Окна командной строки на Windows.** «Обновить и перезапустить» не открывает мигающие окна `cmd`. Новый процесс стартует напрямую и ждёт, пока закроется старый, без `cmd`, `tasklist` и `find`. Другие команды, которые запускает программа, тоже идут без окна консоли. Автозапуск по-прежнему пишет ключ в реестре и этот путь не вызывает.

## Установка

- Каждый тег сам публикует Norka в Homebrew и Scoop.
- Образцы winget, Scoop и Homebrew в `packaging/` остаются на 1.6.1. Этот выпуск их не меняет. После тега `v1.8.0` workflow `update-manifests` возьмёт версию и хеши из `SHA256SUMS` и откроет отдельный pull request.

## Техническое

- Перед созданием выпуска `scripts/check-release-tag.sh` проверяет три условия: коммит тега входит в `main`, `info.productVersion` в `wails.json` совпадает с номером тега, в коммите есть `docs/releases/<тег>.md`. Если чего-то нет, задача `release` падает и выпуск не создаётся.

## Как обновиться

- **С 1.6.x:** на Windows и macOS нажмите «Обновить и перезапустить». На Linux кнопка «Скачать» открывает ссылку в браузере: программа сама себя не заменяет.
- **Windows:** если обновление в один клик недоступно, закройте Norka и замените старый `norka.exe` новым.
- **macOS:** откройте `norka.dmg` и перетащите Norka в «Программы» с заменой.
- **Linux:** скачайте AppImage, `.deb` или `.tar.gz`, что вам удобнее.

Туннели и настройки сохраняются.

## English

You can import a config by dropping a .toml file onto the Norka window. Release 1.7.0 was not published: its tag pointed at a stale commit and was deleted. This release includes what 1.7.0 was meant to ship, and the changes after that.

## New

- **Drag-and-drop import.** Drop `config.toml` onto the window and Norka runs the same import as the Import button in settings, with the same confirmation. It works in both simple and advanced mode. While the file is over the window, a panel with a dashed border shows. If the file has a different type, or you drop several files at once, Norka shows a hint and changes nothing.

## Fixed

- **Command windows on Windows.** "Update and restart" does not open flashing `cmd` windows. The new process starts directly and waits until the old one exits, without `cmd`, `tasklist`, or `find`. Other commands the program starts also run without a console window. Autostart still writes the registry key and does not use this path.

## Installation

- Every tag publishes Norka to Homebrew and Scoop.
- The winget, Scoop, and Homebrew samples in `packaging/` stay at 1.6.1. This release leaves them as they are. After the `v1.8.0` tag, the `update-manifests` workflow takes the version and hashes from `SHA256SUMS` and opens a separate pull request.

## Technical

- Before a release is created, `scripts/check-release-tag.sh` checks three things: the tag commit is in `main`, `info.productVersion` in `wails.json` matches the tag, and the commit contains `docs/releases/<tag>.md`. If any check fails, the `release` job fails and no release is created.

## How to update

- **From 1.6.x:** on Windows and macOS press "Update and restart". On Linux, "Download" opens the file in the browser: the app does not replace itself.
- **Windows:** if the one-click update is unavailable, quit Norka and replace the old `norka.exe`.
- **macOS:** open `norka.dmg` and drag Norka into Applications, replacing the previous copy.
- **Linux:** download the AppImage, `.deb`, or `.tar.gz`, whichever you prefer.

Tunnels and settings are kept.
