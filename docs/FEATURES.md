# Флаги функций

Каждая новая возможность Norka включается флагом. Без флага её не добавляют.

Флаги собраны в `internal/features`. У каждого стабильный `id`, значение по умолчанию и два ключа перевода: название и одна строка описания. Состояние лежит в таблице `[features]` файла `config.toml`.

```toml
[features]
profiles = false
quick_search = true
```

Нет ключа — берётся значение по умолчанию. Поэтому старый `config.toml` открывается как раньше. Явное `false` записывается и не подменяется умолчанием при следующей загрузке.

Интерфейс читает флаги через `useFeature('id')` (`frontend/src/features/feature-store.js`). Бэкенд шлёт их методом `GetFeatures` и событием `features:changed`, так что блок появляется и прячется без перезапуска. Выключенная возможность не просто скрыта: не регистрируется её горячая клавиша, не показывается пункт трея и не идёт фоновая работа.

Сейчас в каталоге: профили (по умолчанию выключены), быстрый поиск, уведомления, проверка обновлений, мониторинг трафика, анимации норки, команда SSH, переподключение после сна, статистика туннелей, тур при первом запуске, диагностика, проверка туннеля и автозапуск в трей (по умолчанию включены), автоматизация, фоновый режим и окно без рамки (по умолчанию выключены). Уведомления и мониторинг трафика забрали прежние переключатели, второго рядом нет. Язык интерфейса и хранение паролей в связке ключей флагами не являются.

Тур при первом запуске показывается один раз, если туннелей ещё нет и он не завершён и не пропущен. Отметка лежит в `onboarding_done`. Ссылка «Показать тур снова» в разделе «Функции» запускает его заново. Выключение флага прячет тур и эту ссылку и не стирает отметку.

Автоматизация открывает локальное управление туннелями: команды `norka`, отдельный клиент `norka-cli` и ссылки `norka://`. Пока флаг выключен, слушатель не стартует, а клиент завершается с кодом 1. Выключение не удаляет список туннелей, для которых пользователь уже нажал «Больше не спрашивать». Команды описаны в [CLI.md](CLI.md).

Диагностика (`diagnostics`) по умолчанию включена. Кнопка «Собрать диагностику» в настройках и пункт трея сохраняют zip для отчёта об ошибке. Выключение прячет кнопку и пункт и не удаляет журнал.

Проверка туннеля (`tunnel_diagnostics`) по умолчанию включена. Пункт «Проверка туннеля» в меню «⋯» и кнопка в простом режиме смотрят DNS, порт jump-сервера, вход по ключу и свободный локальный порт. Выключение прячет пункт и кнопку. Проверка ничего не записывает и не отправляет пароль. Это не архив «Собрать диагностику»: флаги независимы.

Автозапуск в трей (`autostart_hidden`) по умолчанию включён. Запись входа в систему получает `--norka-hidden`, и окно при входе не открывается. Выключение возвращает прежнее поведение: окно открывается. Уже созданная запись переписывается при следующем запуске. Сам автозапуск по-прежнему включается отдельным переключателем в общих настройках.

Фоновый режим (`background_mode`) по умолчанию выключен. Пока он выключен, `norkad` пишет, что режим выключен, и завершается с кодом 10. `--force` эту проверку обходит. Само окно в фон пока не уходит: туннели без открытого окна появятся в следующих обновлениях, а сейчас флаг только разрешает запуск `norkad`. Демон не спрашивает пароль. Туннель, которому нужен пароль или passphrase ключа из окна, пропускается, причина пишется в `norkad.log`.

Окно без рамки (`frameless_window`) по умолчанию выключено. Пока оно выключено, окно выглядит как раньше: на Windows своя строка заголовка 32px, на macOS и Linux системная рамка. Включение читается до `wails.Run` и применяется только после перезапуска: шапка страницы становится зоной перетаскивания, на Windows 11 22H2+ боковая панель и шапка полупрозрачные (Mica, GPU включён — иначе программный кадр WebView2 закрывает фон), на более старой Windows фон сплошной, на macOS системные кнопки и скрытый заголовок. На Linux переключатель скрыт, рамка остаётся системной. После переключения настройки просят перезапустить приложение.

Выключение профилей не удаляет сохранённые профили и не останавливает уже запущенные туннели. Профили по-прежнему выключены по умолчанию.

## Как добавить флаг

1. В `internal/features` добавьте константу `ID` и строку в `All`: id, значение по умолчанию, `TitleKey`, `DescriptionKey`.
2. Те же ключи положите в `frontend/src/locales/ru.json` и `en.json`. Набор ключей и плейсхолдеры вида `{name}` должны совпадать, иначе упадёт `internal/i18ncheck`.
3. В интерфейсе завяжите показ на `useFeature('id')`. Отдельный переключатель в настройках не нужен: секция «Функции» строится из каталога.
4. В бэкенде проверьте флаг до фоновой работы, горячей клавиши и пункта трея. Выключение не должно стирать данные пользователя.
5. Если у возможности уже был свой on/off, перенесите его в реестр и оставьте текущее значение пользователя. Два переключателя на одно и то же не показывайте.
6. Допишите тест: значение по умолчанию, отсутствие ключа, явное `false` после сохранения и загрузки.

Пользователь включает флаг в **Настройки → Функции**.
