# Подпись и проверяемость сборок

## Сейчас

Релизы выходят без подписи кода.

- Windows: `norka.exe` без сертификата издателя. SmartScreen пишет, что издатель неизвестен. Что нажать и как сверить файл — в README, раздел «Windows предупреждает о неизвестном издателе».
- macOS: ad-hoc подпись (`codesign --sign -`). Сертификата Apple Developer ID в этом репозитории нет.
- Linux: AppImage, deb и tar.gz без подписи пакета.

На каждом выпуске рядом с файлами лежит `SHA256SUMS`: строка — SHA256, два пробела, имя файла. Приложение сверяет с ним сборку, если GitHub не отдал digest.

На теге `v*` задача `release` в `.github/workflows/build.yml` вызывает `actions/attest-build-provenance` для `norka.exe`, `norka.dmg`, AppImage, deb и tar.gz. На pull request эта задача не запускается. Проверка локального файла:

```bash
gh attestation verify norka.exe --repo norka-app/Norka
```

Команда считает хеш файла и ищет аттестацию этого репозитория с тем же хешем. Так видно, что байты собрал workflow репозитория. Сертификата издателя Windows у файла от этого не появляется.

## Почему подписи нет

Автор проекта — частное лицо из России. Обычные способы получить кодовый сертификат ему недоступны.

- Azure Artifact Signing (раньше Trusted Signing) выдаёт сертификаты частным лицам только из США и Канады.
- Certum, Sectigo и DigiCert не обслуживают Россию.
- EV-сертификат с 2024 года больше не даёт мгновенной репутации SmartScreen. Подписанный новым сертификатом файл всё равно может показывать предупреждение, пока репутация не накопится по скачиваниям.

## Что планируется

- **Microsoft Store и MSIX.** Пакет из магазина подписывает Microsoft. Установка оттуда обычно не показывает окно про неизвестного издателя.
- **SignPath Foundation** для открытых проектов. Подпись бесплатная, если фонд примет заявку. Подавать её стоит, когда у Norka появится репутация. Шага в workflow нет: его добавляют по инструкции фонда после одобрения. Имя файла в релизе остаётся `norka.exe`, иначе проверка обновлений его не найдёт. Секрет в этот репозиторий фонд не кладёт: подписывает их GitHub App.

## Запасной вариант

В задаче `build-windows` остаются два необязательных шага. Секретов нет — оба пропускаются, в релиз уходит тот же неподписанный `norka.exe`. Имя файла не меняется. Оба сразу не применяются: PFX запускается только когда шаг Azure пропущен.

Это не основной путь. Шаги оставлены на случай, если сертификат всё же появится.

### Azure Artifact Signing

Шаг `azure/trusted-signing-action@v2.0.0` запускается, только когда все шесть секретов непустые. Имена в GitHub → Settings → Secrets and variables → Actions:

| Секрет | Откуда |
|---|---|
| `AZURE_TENANT_ID` | каталог Microsoft Entra (tenant id) |
| `AZURE_CLIENT_ID` | приложение, которому разрешено подписывать |
| `AZURE_CLIENT_SECRET` | секрет этого приложения |
| `AZURE_SIGNING_ENDPOINT` | региональный endpoint аккаунта из портала Azure |
| `AZURE_SIGNING_ACCOUNT` | имя аккаунта Artifact Signing |
| `AZURE_CERT_PROFILE_NAME` | имя профиля сертификата |

Как завести их один раз:

1. В портале Azure создайте аккаунт Artifact Signing и профиль сертификата публичного доверия. Пройдите проверку личности, без неё профиль не заработает.
2. Зарегистрируйте приложение в Microsoft Entra. Создайте client secret.
3. Роль приложения на аккаунте подписи: **Artifact Signing Certificate Profile Signer** (на профиле или на аккаунте).
4. Endpoint скопируйте со страницы аккаунта. Он должен совпадать с регионом, где созданы аккаунт и профиль.
5. Впишите шесть секретов под именами из таблицы.

Новый тег `v*` подпишет `build/bin/norka.exe` до загрузки в релиз. Фильтр — файлы `exe` в этой папке, без вложенных каталогов. Метка времени — `http://timestamp.acs.microsoft.com`, алгоритм SHA256. Поля действия: `endpoint`, `signing-account-name`, `certificate-profile-name`.

### Свой сертификат (PFX)

Шаг вызывает `packaging/windows/sign-pfx.ps1`, только если Azure пропущен и задан `WINDOWS_PFX_BASE64`.

| Секрет | Откуда |
|---|---|
| `WINDOWS_PFX_BASE64` | содержимое `.pfx` в base64, одной строкой |
| `WINDOWS_PFX_PASSWORD` | пароль. Если пароля нет, секрет оставьте пустым — скрипт не передаёт `/p` |

Получить base64 локально, не коммитя файл:

```bash
base64 -w 0 codesign.pfx
```

На Windows:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("codesign.pfx"))
```

Скрипт вызывает `signtool` из Windows SDK (он есть на `windows-latest`): SHA256, метка времени `http://timestamp.digicert.com`. Временный PFX удаляется в `finally`. Пароль в репозиторий не пишется; GitHub маскирует значение секрета в журнале.

Новый сертификат часто выдают только на токен или в облачный HSM, без файла PFX. Тогда этот шаг не подходит.
